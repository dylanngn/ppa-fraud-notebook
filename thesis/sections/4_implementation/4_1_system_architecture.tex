\section{System Architecture Overview}
\label{sec:4_1}

The fraud detection framework implements a modular pipeline architecture separating data processing, feature engineering, graph construction, model training, and real-time inference into distinct components.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=1.1\textwidth,height=0.75\textheight,keepaspectratio]{figures/fig_4_4_1_1.png}
    \caption{System Architecture: Data Layer → ETL Pipeline → Feature Layer → Model Layer → Serving Layer}
    \label{fig:4_1}
\end{figure}

The architecture is designed as a layered system, where each component has a single, well-defined responsibility:

\paragraph{Data Layer}
This layer is responsible for ingesting raw CSV files from the SMG data warehouse, including the main insertion events and SEON transaction logs. These sources often use different timestamp formats, which are standardized at this stage.

\paragraph{ETL Pipeline}
The ETL pipeline merges event and SEON data using temporal "as-of" joins. This is implemented using the Polars library, which allows for memory-efficient processing of over 800,000 events. The pipeline also handles the anonymization of personally identifiable information (PII) and filters the data based on temporal criteria. The final output is stored in compressed Parquet format to speed up downstream processing.

\paragraph{Feature Layer}
The feature layer performs three main functions: it extracts features according to our defined schema, handles the temporal splitting of the data (including a 7-day gap to prevent label leakage), and constructs the heterogeneous graph. This graph contains approximately 31 million edges that link listings through shared devices, IP addresses, emails, and phone numbers.

\paragraph{Model Layer}
The model layer implements our hybrid architecture. A GraphSAGE model extracts 16-dimensional node embeddings from the heterogeneous graph, which are then combined with 65 base features for the final XGBoost classifier. We also implemented several baseline models, such as Logistic Regression and Random Forest, to serve as a point of comparison.

\paragraph{Serving Layer}
For real-time use, the serving layer provides an inference service built with FastAPI. It includes an internal event store that allows it to compute graph features for incoming listings on the fly. The service maintains a sliding window of recent activity to ensure that new listings can be connected to the existing graph.

\paragraph{Monitoring}
The system tracks prediction drift using the DDM (Drift Detection Method) and ADWIN (Adaptive Windowing) algorithms. This monitoring is essential for identifying when a model's performance begins to degrade due to shifting fraud tactics, which then triggers a new retraining cycle.

All these components are orchestrated using Hydra for configuration management and MLflow for experiment tracking. The modular nature of the design means that individual parts—such as the GNN architecture—can be swapped out or upgraded with minimal impact on the rest of the pipeline.

\subsection{Project Structure}

The implementation is organized into distinct packages to maintain a clear separation of concerns. At the root, the \texttt{conf/} directory holds the ETL configurations, while the \texttt{configs/} directory contains the settings for our training experiments and hyperparameter optimization. Any orchestration logic for running complex workflows is located in the \texttt{scripts/} folder.

The core logic of the system resides in the \texttt{src/} directory, which is divided into several functional modules:

\paragraph{Key Modules}
\begin{itemize}
    \item \texttt{src/data/}: Contains the ETL pipeline logic, including scripts for data extraction, transformation, and loading, with full support for streaming via Polars LazyFrames.
    \item \texttt{src/features/}: Manages the feature schema, the feature store, the temporal splitting logic, and the construction of the heterogeneous graph.
    \item \texttt{src/models/}: Includes the base classes and concrete implementations for all our models, from the simple baselines to the hybrid GraphSAGE and XGBoost architecture.
    \item \texttt{src/training/}: Houses the training pipelines for both single-window and expanding-window experiments.
    \item \texttt{src/evaluation/}: Provides tools for SHAP-based explainability and the implementation of our drift detection algorithms.
    \item \texttt{src/api/}: Contains the FastAPI service and the in-memory event store used for real-time inference.
\end{itemize}

This modular structure allows for independent development, testing, and maintenance of each part of the system. For a complete view of the directory layout and implementation details, please refer to Appendix~B.
